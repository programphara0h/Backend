## Introduction to the Internet

### what is a switch and why do we need it?

Say you have 7 pc and your boss wants all these pc to be able to communicate with each other. But how to get all these PCs to comm with each other. This is where the **switch** come into play. The Switch is the device we used for computers/PCs in the same environment to comm with each other. When talking about same environment, it means that computers in the same office, house or work.


Now, we have 7 PC and a switch device, can the PC communicate with each other? No because these PC are not connected to each other and in order to fix that, we need cables to connect these PC to the switch. The typical cables are the copper cable (CAT5 or CAT6). In addition to this, some switch device support fiber optic cable as well and fiber optic cables are generally faster compared to copper cables.

*P/S, CAT means category and the higher the number, the faster the speed*

Also, please note that if there is switch in the environment, and if you want to connect computers to that switch, you must def use a cable that has generally a copper cable or fiber optic cable. Switch only works with cable.

However, if you want to connect PC in the same environment by using the wireless technology, you can use an **Access Point** device (AP). The only difference between AP and Switch is that AP is wireless and switch is using wired cables be it copper or fiber optic.

Hence, if the PCs are connected either to the switch or AP, then this created a network. These PCs can comm with each other because all of them are in the same network and this network is called as **Local Area Network** (LAN). A LAN is a collection of devices connected together in non-physical location such as office, classroom or home.

#### Packet

Ok now what does LAN actually represent. Say PC1 wants to send a message to PC7. BTW the messages generated by computers has a few special names, and in this study, we are going to call them as **Packet**. Packet is a small segment of a larger message. Data sent over computer networks such as the internet is divided into packets. These packets are then recombined by the computer that receives them. But why use **Packets**? Sending files over the internet as a single, unbroken line of bits is possible but impractical; it blocks the wires, forcing other computers to wait their turn. To solve this, the internet uses packet switching, which chops data into small, independent packets that can take different paths to the same destination. This allows packets from billions of devices to share the same wires simultaneously in any order, enabling massive, worldwide simultaneous connections.


##### Packet Header

A **packet header** is the information attached to the front of every packet before it is sent across a network. Think of it like the shipping label on a package. The package contains the actual item you are sending, while the shipping label contains instructions that tell the delivery company where the package should go and how it should be handled. Similarly, a packet consists of two parts: the **header**, which contains networking information, and the **payload**, which contains the actual data, such as part of a webpage, an image, or a video.

The header exists because network devices, such as routers and switches, do not care about the contents of your data. Their only responsibility is to deliver it to the correct destination. Just as a postal worker does not open your letter to read its contents, routers do not inspect the payload to decide where to send a packet. Instead, they read the information stored in the packet header and use it to forward the packet to the next device until it reaches its destination.

One of the most important pieces of information in the header is the **source address**, which identifies where the packet came from. Another is the **destination address**, which tells routers where the packet needs to go. Every router along the path examines the destination address and decides the best next hop, much like a GPS continuously choosing the best road toward a destination.

Another important field is the **sequence number**. Large files, such as videos or game downloads, are split into thousands of packets before being transmitted. Since packets may travel through different routes, they can arrive in a different order from how they were sent. The sequence number allows the receiving computer to place every packet back into its correct position so that the original file can be reconstructed accurately.

The header also contains a **checksum**, which is used to detect whether a packet has been corrupted during transmission. The sender calculates a checksum before sending the packet, and the receiver performs the same calculation after receiving it. If the values do not match, the receiver knows the packet was damaged and requests that only the corrupted packet be sent again instead of retransmitting the entire file.

Another field is the **protocol**. This tells the receiving computer what set of communication rules should be used to process the packet. For example, **TCP** provides reliable communication by ensuring packets arrive correctly and in order, while **UDP** prioritizes speed and allows some packet loss, making it suitable for applications such as online gaming or live video streaming.

The **Time To Live (TTL)** field prevents packets from circulating endlessly around the Internet. Every time a packet passes through a router, its TTL value decreases by one. If routing problems create a loop, the TTL will eventually reach zero, causing the router to discard the packet. This mechanism prevents unnecessary network congestion caused by packets that would otherwise travel forever.

It is important to understand that there is not just one header. As data travels down the networking stack, each layer adds its own header for a specific purpose. For example, the **Ethernet header** is used for communication within a local network, the **IP header** is responsible for routing packets across different networks, and the **TCP header** manages reliable delivery, sequencing, and error detection. This process of wrapping data with additional headers is called **encapsulation**.

| Layer / Header | Function / Content |
| :--- | :--- |
| **Ethernet Header** | Local network delivery |
| **IP Header** | Route across the Internet |
| **TCP Header** | Reliability and ordering |
| **HTTP Request** | `GET /watch?v=abc123` |

A useful example is loading YouTube in a web browser. The browser first creates an HTTP request, such as `GET /watch?v=abc123`. The transport layer adds a TCP header, the network layer adds an IP header, and the data link layer adds an Ethernet header. As the packet travels across the Internet, switches mainly use the Ethernet header, routers examine the IP header, and the destination computer removes each header one layer at a time until the original HTTP request reaches the web server.

The key idea to remember is that **the payload is the actual information you want to send, while the header is the metadata that tells the network how to deliver it correctly**. Without headers, routers would not know where packets came from, where they should go, how to verify their integrity, or how to reassemble them in the correct order. In short, **applications care about the payload, but the network cares about the header**.

##### Packet Trailer

Packet headers go at the front of each packet. Routers, switches, computers, and anything else that processes or receives a packet will see the header first. A packet can also have trailers and footers attached at the end. Like headers, these contain additional information about the packet.

Only certain network protocols attach trailers or footers to packets; most only attach headers. ESP (part of the IPsec suite) is one example of a network layer protocol that attaches trailers to packets.
