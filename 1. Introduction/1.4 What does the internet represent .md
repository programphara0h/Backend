## Load Balancing

Load balancing solves the single point of failure problem like the above. Say if 30 routers broke down out of 1 million routers, the internet still continues to work properly, and nothing came crashing down. Only the affected network efficiency was reduced a bit because of router breakdown. 

## How a packet moves on the internet

In this subtopic you will understand how devices in different countries communicate with each other. First, the computer sends the packet to the router. The router examines the destination IP address in the packet header and uses this information to determine where the packet should be sent next. Hence it sends the packet to the internet because the destination of the packet is different network than its own LAN. So, The router forwards the packet through the physical connection to the ISP network (for example, fiber optic), where ISP routers continue forwarding the packet. Considering there are millions of routers in the world, the packet will hop from one router to another, but here is the important part, the packet itself does not have options or choose which path to take. It is the routers that decide that and they do it strictly based on rules, not by freely picking among many options.

Note: But before we proceed to that, first you must understand that each router must have a special table called Routing Table. This table tells us which next-hop router the packet should be sent to, and after that the router will send the packet to that designated router. This process is called forwarding. As a result, every router needs to look at its routing table to learn which interface it must forward the packet out of. Aside from that, routers also have special processors inside, whereas these processors run routing protocols (like OSPF or BGP) that exchange information with neighboring routers. Using that information, the processors run algorithms to build the routing table. When forwarding packets, routers use rules such as longest prefix match to select the most specific route. When building the routing table, routers use routing protocol rules, administrative distance, and metrics to decide which routes are preferred.

This process of lookup-and-forward will keep on happening at every router until it finally reaches the destination device. But important to note that the routing table takes many variables into account before deciding which route the packet must go. Because when routers build their routing table, they are NOT only concerned about the number of hops in order to choose the SHORTEST route, they also consider bandwidth, delay, reliability, and even administrative policies.

However, here is the big correction: congestion control is NOT the router looking at live traffic and switching to another route because route1 is busy. In real life, standard internet routers do not check packet density per packet and change their mind. Instead, congestion control is actually a feature of the sending device (like your computer using TCP) that slows down its sending speed when it detects the network is getting too crowded. As for the router, if its routing table says "send out interface 1", it will send it out interface 1 even if that interface is overloaded unless the network administrator manually changes the settings or the link physically fails, which triggers the routing protocol to recalculate a new table. So the router does not dynamically avoid a busy route on a packet-by-packet basis; it follows the table that was built using those fixed rules and metrics and routers generally have QoS (Quality of Service), queue management, load balancing, traffic engineering etc.

*PS Note: The routers mentioned in this explanation refer to network routers operated by ISPs, companies, data centers, and internet backbone providers, not personal home routers. A packet does not travel by hopping through random users' home routers. Your home router only acts as the default gateway that connects your local network (LAN) to your ISP. After leaving your home network, the packet travels through the ISP's own routing infrastructure and other large-scale network routers until it reaches the destination network.*
