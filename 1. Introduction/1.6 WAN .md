## Wide Area Network (WAN)

# WAN — Part 1: Fundamentals and How WAN Fits into Networking

## 1. What is a WAN?

**WAN stands for Wide Area Network.**

A WAN is a network that connects **separate networks over a large geographical area**, such as different buildings, cities, states, or countries.

The easiest way to remember it is:

> **LAN connects devices locally. WAN connects separate networks over a large distance.**

For example, a company may have a LAN in its Kuala Lumpur headquarters and another LAN in its Johor Bahru branch:

```text
Kuala Lumpur LAN                    Johor Bahru LAN
      │                                   │
   Router                               Router
      │                                   │
      └────────────── WAN ────────────────┘
```

The WAN provides connectivity between these two locations so that devices on the different LANs can communicate.

---

# 2. LAN vs WAN

A **LAN (Local Area Network)** covers a relatively small area, such as a home, office, or building.

```text
Office LAN

PC ─┐
PC ─┤
PC ─┤── Switch ── Router
PC ─┘
```

A **WAN** connects networks that are geographically separated.

```text
Office A LAN                    Office B LAN
     │                               │
   Router                          Router
     │                               │
     └──────────── WAN ──────────────┘
```

Therefore:

**LAN → local network**

**WAN → connection between geographically separated networks**

---

# 3. WAN does NOT mean "the Internet"

WAN and the Internet are related, but they are not the same thing

**WAN** describes the **scope and architecture of a network**.

**The Internet** is the **global public network of interconnected networks**.

A company can connect its branches using:

```text
Option 1: Private WAN

KL LAN
  │
Router
  │
Private WAN
  │
Router
  │
JB LAN
```

or:

```text
Option 2: Public Internet

KL LAN
  │
Router
  │
Internet
  │
Router
  │
JB LAN
```

Both can provide connectivity between the two geographically separated LANs.

Therefore, a company does **not necessarily need a dedicated private WAN service** just because it needs to connect two locations.

It can use the public Internet, often together with technologies such as VPNs and other security mechanisms.

---

# 4. Why do we even call it a WAN if we can just use the Internet?

This is the important distinction.

Suppose Maybank has:

```text
Maybank KL                         Maybank JB
     LAN                               LAN
      │                                 │
   Router                            Router
      │                                 │
      └──────────── Internet ───────────┘
```

A packet can travel from the KL network to the JB network through the Internet.

There is no requirement for Maybank to purchase a dedicated private WAN connection.

However, the Internet is providing **wide-area connectivity** between the two locations.

Therefore:

> **WAN is not necessarily a specific service that you buy. It describes networking between geographically separated locations.**

A **private WAN** is one particular way of providing that connectivity.

This is why saying:

> "Why do I need a WAN? I'll just use the Internet."

is not really a contradiction.

You are essentially saying:

> "I'll use the Internet as my wide-area connectivity instead of using a dedicated private WAN."

---

# 5. The Internet and WAN

The Internet itself is made up of many interconnected networks operated by different organizations, including ISPs, telecommunications companies, cloud providers, universities, businesses, and other network operators.

A simplified view is:

```text
Home / Office LAN
       │
    Router
       │
      ISP
       │
   WAN-scale
   networks
       │
   Other ISPs
       │
Destination Network
       │
Destination LAN
```

Therefore, the Internet and WAN should not be thought of as competing concepts.

The Internet provides a **public global network**, while WAN describes the **wide-area networking concept**.

---

# 6. What does a router have to do with WAN?

A **router connects different networks and forwards packets between them**.

Suppose:

```text
KL LAN
192.168.10.0/24
       │
       ▼
   KL Router
       │
       ▼
WAN / Internet
       │
       ▼
   JB Router
       │
       ▼
JB LAN
192.168.20.0/24
```

A computer in the KL LAN wants to communicate with a computer in the JB LAN.

The destination is outside the local network, so the packet is sent to the router.

The router examines the destination IP address and determines where the packet should be forwarded next.

The packet may pass through multiple routers before reaching the destination network.

---

# 7. Example: A packet travelling from KL to JB

A simplified journey could look like:

```text
KL Computer
     ↓
KL LAN
     ↓
KL Router
     ↓
ISP / WAN
     ↓
Multiple Routers
     ↓
JB Router
     ↓
JB LAN
     ↓
JB Server
```

Each router along the path performs forwarding decisions.

The exact route depends on the network's routing information and current network conditions.

The important concept is:

> **A packet can leave one LAN, travel through multiple interconnected networks, and eventually enter another LAN.**

---

# 8. WAN and HTTPS are completely different concepts

This is one of the easiest things to confuse.

**WAN provides network connectivity.**

**HTTPS provides secure communication for HTTP applications.**

For example, when you open an HTTPS website:

```text
Your Computer
     ↓
LAN
     ↓
Router
     ↓
ISP / Internet
     ↓
Destination Network
     ↓
Web Server
```

HTTPS operates between the web application and the web server.

It does **not create the physical/network path between your computer and the server**.

A useful mental model is:

> **WAN/Internet = the road**
>
> **IP = addressing and routing**
>
> **TCP = transport**
>
> **HTTPS = secure web communication travelling over the network**

Therefore, HTTPS does not replace WAN connectivity.

---

# 9. How the networking layers fit together

A simplified view is:

```text
Application
     ↓
HTTPS / HTTP
     ↓
TCP / UDP
     ↓
IP
     ↓
LAN / WAN / Internet
     ↓
Physical network infrastructure
```

Each layer has a different responsibility.

**HTTPS** → secures HTTP communication.

**TCP/UDP** → provides transport mechanisms.

**IP** → provides addressing and packet forwarding between networks.

**LAN/WAN** → describes the network environment and geographical scope.

**Fiber/cellular/etc.** → provides the underlying transmission infrastructure.

---

# 10. Packet switching

Modern computer networks, including the Internet, primarily use **packet switching**.

Instead of sending an entire piece of data as one continuous transmission, data is divided into smaller units called **packets**.

For example:

```text
Large data
     ↓
┌────────┬────────┬────────┐
│Packet 1│Packet 2│Packet 3│
└────────┴────────┴────────┘
```

Each packet contains information such as source and destination addressing.

Routers examine the destination information and forward packets toward their destination.

Packets can potentially take different paths through a packet-switched network.

At the destination, the data can be reconstructed by the appropriate protocols.

---

# 11. Circuit switching

**Circuit switching** is a different networking approach.

A dedicated communication path is established between two endpoints, with network resources reserved for that connection.

A traditional telephone network is a classic example.

Conceptually:

```text
Device A
   │
   ├──── dedicated path ────┐
   │                        │
   └──────────────────── Device B
```

Modern data networks such as the Internet primarily use **packet switching** rather than traditional circuit switching.

---

# 12. TCP/IP and WAN

**TCP/IP** is a suite of networking protocols used to communicate across interconnected networks.

Two important protocols are:

### IP — Internet Protocol

IP provides addressing and allows packets to be forwarded between networks.

For example:

```text
Source IP       → Destination IP
192.168.1.20    → 203.0.113.50
```

Routers use the destination IP address when making forwarding decisions.

### TCP — Transmission Control Protocol

TCP provides reliable, ordered delivery between applications when TCP is being used.

Therefore:

> **IP helps get packets between networks; TCP helps provide reliable communication between applications.**

---

# 13. WAN infrastructure

WAN connectivity can use different types of physical or telecommunications infrastructure, including:

* Fiber-optic cables
* Cellular networks
* Satellite links
* Microwave/radio links
* Telecommunications carrier networks
* Internet connections

The important distinction is:

> **WAN describes the wide-area networking arrangement; fiber, cellular, satellite, etc. are ways of carrying the traffic.**

---

# 14. Advantages of WAN

### Geographical connectivity

WANs allow organizations to connect offices and systems across cities, countries, or continents.

### Resource sharing

Authorized users at different locations can access shared systems, applications, databases, and other resources.

### Centralized systems

An organization can maintain important systems in one location while allowing other branches to access them.

### Remote communication

Employees and systems in different locations can communicate without being physically connected to the same LAN.

---

# 15. Challenges of WAN

### Higher latency

Longer physical distances generally result in greater latency.

```text
Same building
     ↓
Lower latency

Malaysia → Europe
     ↓
Higher latency
```

### Greater complexity

A WAN may involve many routers, links, ISPs, firewalls, VPNs, telecommunications providers, and other infrastructure.

### Cost

Dedicated enterprise WAN services can be expensive.

### More potential failure points

A WAN may contain many devices and links. Organizations therefore often use redundancy, such as multiple links, to improve reliability.

---

# 16. Core WAN mental model

Remember this:

```text
LAN
= connects devices locally

WAN
= connects separate networks over large geographical distances

Router
= connects networks and forwards packets

Internet
= global public network of interconnected networks

Private WAN
= WAN connectivity controlled/provisioned for an organization

IP
= addressing and packet forwarding between networks

Packet
= unit of data travelling through a network

HTTPS
= secure communication for HTTP applications
```

The most important concept is:

> **WAN is about connecting networks across distance. It does not necessarily mean a dedicated private connection. The public Internet can provide that wide-area connectivity.**


# WAN — Part 2: WAN Technologies

## 1. How is a WAN actually implemented?

A WAN is a concept: **connecting geographically separated networks**.

To actually create that connectivity, organizations use different technologies and services.

For example:

```text id="3g7q8m"
                 WAN
                  │
       ┌──────────┼──────────┐
       │          │          │
    Internet     MPLS     Cellular
       │
     VPN
       │
    SD-WAN
```

These technologies are not all alternatives to "WAN."

They are **different ways of providing, transporting, managing, or securing WAN connectivity.**

---

# 2. Dedicated / Private WAN

An organization can purchase or establish a private connection between its locations.

For example:

```text id="9j0b8e"
Company HQ                         Branch
   │                                  │
 Router                             Router
   │                                  │
   └─────── Private WAN ──────────────┘
```

The organization does not necessarily own every physical cable involved.

A telecommunications provider may own the underlying infrastructure and provide the organization with a private WAN service.

This can give the organization greater control over connectivity, routing, performance, and security.

---

# 3. Leased Lines

A **leased line** is a dedicated telecommunications connection leased from a service provider.

For example:

```text id="0f0w4r"
Company A
   │
Router
   │
Leased connection
   │
Telecom Provider
   │
Leased connection
   │
Router
   │
Company B
```

The company pays the provider for dedicated connectivity between locations.

Historically, leased lines were an important method of connecting geographically separated offices.

The important idea is:

> **A leased line provides dedicated connectivity between locations through a telecommunications provider.**

---

# 4. The Public Internet as WAN Connectivity

A company does not always need a dedicated private WAN connection.

It can use the public Internet:

```text id="5p1vqh"
Office A
   │
Router
   │
ISP
   │
Internet
   │
ISP
   │
Router
   │
Office B
```

This is often cheaper and more flexible than dedicated connectivity.

However, the public Internet is shared infrastructure, so organizations may use additional technologies such as **VPNs** to create secure communication between locations.

---

# 5. VPN

**VPN stands for Virtual Private Network.**

A VPN creates a protected logical connection over an existing network, often the public Internet.

For example:

```text id="q9t9hf"
KL Office
   │
Router
   │
Internet
   │
Encrypted VPN tunnel
   │
Internet
   │
Router
   │
JB Office
```

The physical traffic still travels across the Internet, but the VPN can create a secure tunnel between the two locations.

Therefore:

> **VPN does not replace the Internet. It uses an existing network to create a protected logical connection.**

A **site-to-site VPN** can connect two entire networks:

```text id="u9e9tx"
KL LAN
   │
VPN Gateway
   │
==== Encrypted Tunnel ====
   │
VPN Gateway
   │
JB LAN
```

This allows authorized devices in the two locations to communicate through the VPN.

---

# 6. MPLS

**MPLS stands for Multiprotocol Label Switching.**

MPLS is a technology commonly used in telecommunications and enterprise networks.

The basic idea is that traffic can be forwarded through a provider network using **labels**.

Instead of every MPLS router needing to make forwarding decisions solely by repeatedly examining the full IP routing information, MPLS can associate a label with traffic and use that label to guide forwarding.

Simplified:

```text id="p0d0hv"
Packet
   ↓
MPLS Router
   ↓
[Label]
   ↓
MPLS Network
   ↓
Next Router
   ↓
Destination
```

The exact MPLS process is more complicated, but at this stage remember:

> **MPLS is a WAN technology that can use labels to efficiently direct traffic through a provider network.**

MPLS is **not the same thing as WAN**.

Think:

```text
WAN
 └── MPLS = one technology that can be used for WAN connectivity
```

---

# 7. Why did organizations use MPLS?

Organizations may have many locations:

```text id="2a1u6c"
                 HQ
                 │
          ┌──────┼──────┐
          │      │      │
        Branch  Branch  Branch
          A       B       C
```

They need reliable connectivity between them.

An MPLS service from a telecommunications provider can provide a managed network connecting those locations.

Historically, MPLS was particularly popular for enterprise WANs because it could provide predictable connectivity and traffic management.

However, organizations can also use Internet connections, VPNs, SD-WAN, and combinations of these technologies.

---

# 8. SD-WAN

**SD-WAN stands for Software-Defined Wide Area Network.**

SD-WAN is a software-driven approach to managing WAN connectivity.

An organization may have multiple connections available:

```text id="t7q4r5"
                  Office
                    │
                 SD-WAN
              ┌─────┼─────┐
              │     │     │
            MPLS  Internet  5G
```

Instead of treating each connection independently, SD-WAN can use software-defined policies to decide how traffic should use these connections.

For example:

```text id="5kq8x7"
Video conference → preferred high-quality link

Normal web traffic → Internet

Backup traffic → cheaper available link
```

SD-WAN can also monitor network conditions and potentially move traffic between links when conditions change.

---

# 9. Why SD-WAN became useful

Imagine a company has:

```text id="3ng99f"
Branch
  │
  ├── MPLS
  ├── Fiber Internet
  └── 5G
```

Without intelligent management, the organization may have to configure and manage these connections separately.

SD-WAN provides a centralized software-driven way to manage the WAN.

It can consider factors such as:

* Application requirements
* Link availability
* Latency
* Packet loss
* Bandwidth
* Security policies
* Cost

The important idea is:

> **SD-WAN is not a new physical cable or replacement for the Internet. It is a software-defined way of managing multiple WAN connections.**

---

# 10. MPLS vs SD-WAN

These are often mentioned together, but they are different.

### MPLS

A **network technology** used to forward traffic through a provider network using labels.

### SD-WAN

A **software-defined approach to managing WAN connectivity and traffic policies**.

For example, SD-WAN could manage:

```text id="lj3j1g"
              SD-WAN
                 │
        ┌────────┼────────┐
        │        │        │
      MPLS    Internet    5G
```

So they can actually be used **together**.

---

# 11. Fiber Optic and WAN

Fiber optic is a **physical transmission medium**, not a WAN protocol.

For example:

```text id="4j1w6w"
Computer
   ↓
Router
   ↓
Fiber optic
   ↓
Provider network
   ↓
Fiber optic
   ↓
Router
   ↓
Destination
```

Fiber uses light transmitted through optical fibers to carry data over long distances.

It is widely used in telecommunications and Internet infrastructure because it can provide very high bandwidth over long distances.

Remember:

> **Fiber = physical medium**
>
> **WAN = network architecture/scope**

---

# 12. Cellular and Satellite WAN Connectivity

WAN connectivity does not have to use physical cables all the way to the endpoint.

### Cellular

A branch could use a 4G/5G connection:

```text id="v5x5jb"
Office
  │
5G Router
  │
Cellular Network
  │
Internet / Provider Network
```

### Satellite

A remote location could communicate through a satellite link:

```text id="f6o1o6"
Remote Office
     │
Satellite Dish
     │
Satellite
     │
Ground Station
     │
Network
```

These are examples of different ways to obtain wide-area connectivity.

---

# 13. WAN Protocols and Technologies

Some older WAN technologies you may encounter in networking material include:

### Frame Relay

An older packet-switched WAN technology used to connect geographically separated locations.

### ATM

**Asynchronous Transfer Mode** is another older WAN technology that used fixed-size cells for transporting data.

### SONET/SDH

**SONET (Synchronous Optical Networking)** and **SDH (Synchronous Digital Hierarchy)** are telecommunications standards historically used to transport data over optical networks.

**Packet over SONET/SDH (PoS)** allowed packet-based traffic to be transported over SONET/SDH infrastructure.

These technologies are important for understanding the **history of WAN networking**, but you are less likely to encounter them in a modern basic network deployment than technologies such as Ethernet, IP, fiber, VPN, MPLS, and SD-WAN.

---

# 14. WAN Technologies vs Protocols vs Physical Infrastructure

Do not put all networking terms into the same category.

They describe different things.

| Term        | What it is                                                |
| ----------- | --------------------------------------------------------- |
| WAN         | Network scope/architecture                                |
| Internet    | Global public network of interconnected networks          |
| Private WAN | Organization-controlled WAN connectivity                  |
| Fiber optic | Physical transmission medium                              |
| Cellular    | Wireless network technology                               |
| MPLS        | Traffic-forwarding/network technology                     |
| SD-WAN      | Software-defined WAN management approach                  |
| VPN         | Protected logical connection over another network         |
| IP          | Network-layer protocol for addressing and forwarding      |
| TCP         | Transport-layer protocol                                  |
| HTTPS       | Secure application-layer HTTP communication               |
| Router      | Device that forwards packets between networks             |
| Packet      | Unit of data transmitted across a packet-switched network |

This distinction prevents a lot of confusion.

---

# 15. Putting everything together

Imagine a company has offices in Kuala Lumpur, Johor, and Penang.

The company could design its network like this:

```text id="5i6x8f"
                       COMPANY WAN
                            │
                    ┌───────┼───────┐
                    │       │       │
                   KL      JB     Penang
                  LAN     LAN       LAN
                    │       │       │
                  Router  Router   Router
                    │       │       │
                    └───────┼───────┘
                            │
                     WAN Connectivity
```

That WAN connectivity could be provided using:

```text id="i3k7qf"
             WAN Connectivity
                    │
       ┌────────────┼────────────┐
       │            │            │
     MPLS       Internet       5G
                    │
                   VPN
```

And SD-WAN could manage these different connections:

```text id="4eqx8x"
                    SD-WAN
                       │
          ┌────────────┼────────────┐
          │            │            │
        MPLS        Internet       5G
```

Underneath all of this, physical infrastructure such as fiber optic cables, cellular networks, and other telecommunications infrastructure carries the actual data.

---

# 16. A complete packet journey

Suppose an employee in Maybank KL accesses an internal application hosted in JB.

One possible architecture could be:

```text id="a3s3f9"
Employee PC
     │
     ▼
KL LAN
     │
     ▼
KL Router
     │
     ▼
SD-WAN / VPN / MPLS
     │
     ▼
WAN / Provider Network
     │
     ▼
JB Router
     │
     ▼
JB LAN
     │
     ▼
Application Server
```

The actual implementation could be different.

For example, the company might instead use:

```text
KL → Internet → Site-to-Site VPN → JB
```

or:

```text
KL → MPLS → JB
```

or:

```text
KL → SD-WAN → Internet/MPLS/5G → JB
```

The fundamental purpose remains the same:

> **Connect the geographically separated networks.**

# 17. The hierarchy to remember

When studying WAN, organize the concepts like this:

```text
WAN
│
├── Purpose
│     └── Connect geographically separated networks
│
├── Connectivity
│     ├── Private WAN
│     ├── Internet
│     ├── Leased lines
│     ├── MPLS
│     ├── Cellular
│     └── Satellite
│
├── Security / Logical connectivity
│     └── VPN
│
├── WAN management
│     └── SD-WAN
│
└── Physical infrastructure
      ├── Fiber optic
      ├── Copper
      ├── Radio
      └── Satellite
```

This hierarchy is much easier to remember than treating every term as if it were another type of WAN.

---

# 18. Final mental model

When you see a networking question involving WAN, think:

**Step 1 — What networks are being connected?**

```text
LAN A ───────── LAN B
```

**Step 2 — How are they connected?**

```text
Internet?
MPLS?
Private WAN?
Leased line?
5G?
```

**Step 3 — Is the traffic protected?**

```text
VPN?
Firewall?
Other security mechanisms?
```

**Step 4 — How is the WAN managed?**

```text
Traditional routing?
SD-WAN?
```

**Step 5 — What physically carries the traffic?**

```text
Fiber?
Cellular?
Satellite?
```

The core idea never changes:

> **WAN connects geographically separated networks. The technologies such as MPLS, VPN, SD-WAN, leased lines, fiber, cellular, and satellite are different ways of providing, transporting, securing, or managing that connectivity.**
